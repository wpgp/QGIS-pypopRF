    Settings

    Settings are saved in the project's config.yaml. Opening a project restores its existing configuration. Every analysis also saves run_config.yaml with all effective defaults and canonical input paths, so a later default change does not silently change the recorded settings of an earlier run.

    Set up a first run

    1. Open the intended project and finish any import/compatibility checks in Input data.
    2. In Settings, enter the exact CSV Zone identifier and Population total names. For zone_code,people, use zone_code and people; there is no automatic renaming of your source columns. The optional age-sex table uses the same identifier name.
    3. Keep the default log transform and selection threshold for a first test unless your study design justifies a change. Start with a modest worker budget; leave raster tiling enabled.
    4. Review the selection checklist, then use Run analysis in the footer. It still validates the actual files and support in the separate engine.

    Controls save project configuration; opening an existing project restores its values rather than replacing them with new-project defaults. Do not change configuration or inputs while an import, preparation or calculation is running.

    Controls in the Settings tab

    Add population maps to QGIS On Adds verified population maps after successful completion.
    Detail level INFO Selects the amount of diagnostic logging.
    Log filename logs_pypoprf.log A plain .log filename, without directories or reserved device names.

    Target, selection and resource use

    The target density is population divided by the number of eligible mastergrid pixels in each census zone. It does not depend on the ordering of covariates. It is not a value in people/km² unless a separate unit conversion is performed. Water-excluded/invalid grid pixels are not eligible. The optional constraint limits the additional constrained population output, not this training target.

    Feature importance is an increase in validation RMSE, normalized by the larger of the training target standard deviation and mean absolute target. It is not a probability or a cumulative share of features. If the threshold excludes every useful feature, the best positive feature is retained. With no credible positive ranking, a constant target or a very small training subset, all features are retained. Selection is fitted within each outer training fold.

    Permutation selection uses an inner holdout and the current training target scale: log1p(density) when the log option is on, raw density when off. Do not compare importance magnitudes across transform choices as though they were the same raw-density score. Outer CV metrics, by contrast, are computed after inversion in raw population-per-eligible-pixel density units.

    Both processing modes read bounded raster tiles. Disabling parallel tile processing selects serial execution; it does not request a full-grid read. Prediction also writes tiled windows. Worker count and tile dimensions affect resource usage. Using every CPU does not necessarily improve speed. The owned engine child caps native BLAS/OpenMP pools to one thread each, preventing an extra native pool per RF worker. This does not change the configured RF worker budget or the QGIS host's environment; the run manifest records loaded native pool counts.

    Advanced configuration

    The following fields are supported in config.yaml but do not currently have dedicated GUI controls. Finish or cancel plugin work and wait until it is idle, save any other QGIS work, then exit QGIS before editing the file. Reopen QGIS and explicitly open the project afterward. Merely closing the plugin dialog hides a reused window; opening its already-active folder again may be a no-op, so that is not a reliable external-config reload.

    Add/change these fields in the existing project configuration. This snippet is not a replacement for its input paths, column mapping and other settings.

    random_seed: 42
n_estimators: 500
cv_folds: 5
cv_strategy: spatial
spatial_grid: [4, 4]
cv_group_column: null

    spatial_grid contains the number of columns and rows of spatial blocks over the full mastergrid footprint. It is a subdivision count, not a distance in metres. Valid-pixel zone centroids determine block membership. All zones in a block remain together in external cross-validation; scaler, selection and forest are refitted on training data only.

    Raster Tile size is an I/O/resource setting; spatial_grid is a validation design. Changing one does not define the other. cv_folds requests at most that many outer folds; the engine reduces it to the number of available groups/zones.

    The default spatial strategy records CRS, pixel/native-unit block dimensions, centroids and limitations. It uses no separation buffer. Large zones can cross the boundaries of their centroid's block, and adjacent blocks can contain dependent observations. Choose the subdivision scale for the study rather than interpreting the default as an estimated autocorrelation distance.

    groups uses a nonmissing census cv_group_column or groups supplied to the Python API. Supplied groups are kept together but are not automatically called spatial validation. shuffled_zone is an explicitly labelled diagnostic split which ignores spatial dependence. When spatial CV has fewer than two occupied blocks, or a training zone has no eligible centroid, metrics are unavailable with an explanation; there is no automatic random fallback.

    Keep cv_group_column: null for automatic spatial blocking. A configured group column or explicit Python-API groups take precedence over automatic blocking; they are labelled user-supplied grouping, not automatically spatial validation. For example, with a nonmissing district_group census column:

    cv_strategy: groups
cv_group_column: district_group

    That column is metadata for splitting, not an extra raster predictor. Justify the grouping scientifically; a shared administrative label alone does not prove independence.

    The run's cv_metrics.json, cv_predictions.csv and cv_zone_geometry.csv record the actual validation. Scores describe held-out zone-average density, not independent fine-pixel accuracy. Compare candidate models only under the same explicitly recorded folds and support rules; a single block partition is not a general fine-pixel accuracy benchmark.

    RMSE and MAE summarize pooled out-of-fold zone-density errors. Normalized RMSE and MAE divide those errors by the mean observed density and are unavailable when that mean is zero. R² is unavailable for a constant observed target; a negative R² can occur. An unavailable score does not authorize changing to a random split merely to obtain a number. With few zones/blocks, interpret any available score cautiously.

    Paths, logs and model files

    data_dir and output_dir are resolved against work_dir; absolute paths are also supported. The GUI creates each run beneath <output_dir>/runs/<run_id>/. Earlier runs are preserved.

    The GUI has a separate diagnostic logger. The engine writes its log into the current run. Logs append and rotate rather than truncating previous content. The headless configuration accepts logging.file: null to disable engine file logging; the GUI currently expects a filename.

    GUI diagnostics use <project>/output/<Log filename>, even if a different analysis output_dir is configured. Each engine run uses its own log in the run folder. Keep log destinations as dedicated ordinary files; aliases/hardlinks and paths inside plugin/engine/job-cache folders are refused.

    The fitted model, scaler, feature order, target transform, versions and training pixel-geometry contract are saved together in model_bundle.pkl.gz. The GUI does not offer model reuse or import. The Python API rejects legacy standalone model/scaler pairs and incompatible bundle environments or grids; retraining is required. Joblib bundles are executable Python serialization and must only be loaded from trusted sources.

    The saved grid contract includes CRS and linear affine pixel geometry: a changed resolution/rotation changes the meaning of population per eligible pixel. A compatible bundle load is not evidence that transfer to new geography is accurate.
