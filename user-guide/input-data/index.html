    Input data

    An analysis needs one zone grid, a population CSV and at least one numeric raster covariate. Optional inputs are a water mask, a population-support mask and an age/sex CSV. Validation reads inputs and does not rename their columns or rewrite source CSV files.

    Choose an input workflow

    Create or open an external project first; see Projects. Then use Input data:

    • Already aligned data: select the zone grid and census CSV, then Add raster files… in the covariate section. Direct import copies files; it does not align them.
    • Data needing alignment or census polygons: with the engine ready, choose Prepare / align inputs…. Check compatibility and create a new prepared project. The wizard does not repair the current project in place.
    • A layer already in QGIS: choose Use a QGIS layer…, select its role, then the layer. This uses a supported local file source, not an arbitrary live or remote provider. Export unsupported layers first or use preparation.

    Selection in the footer is only a checklist. Run analysis performs full numerical validation. A successful copy does not prove that grids, census IDs or predictor support are compatible.

    Raster grid contract

    Use single-band GeoTIFFs with a defined CRS. Mastergrid, covariates and optional masks must have the same CRS, dimensions and complete affine pixel transform: pixel size, origin and rotation all matter. A shifted grid is rejected even if its dimensions match. Small floating-point transform roundoff is tolerated; the engine does not automatically reproject or resample inputs.

    For a new GUI import, use a self-contained GeoTIFF. Imports with external mask or georeferencing sidecars such as .msk, .aux.xml, .tfw, .tifw, .wld or .prj are rejected with export guidance rather than silently losing those resources. A complete dataset already inside the project's data directory can be selected in place, keeping its sidecars. The headless engine records GDAL's input resource list, including available sidecars, in run provenance.

    NoData and GDAL valid-data masks are respected. Ordinary numeric zero is valid unless the raster declares it NoData. Mark missing data correctly rather than using a finite sentinel as an undeclared measurement.

    Zone grid

    Each valid pixel contains the integer ID of its census zone. An ID occurs in many pixels; pixel values do not have to be globally unique. Gaps outside the study area are allowed when marked NoData. IDs must match the population CSV. IDs must be exactly representable integers within the supported numeric range (absolute value no greater than 2**53).

    Zero is a valid zone ID if it is not declared NoData. Numeric IDs such as 1 and 1.0 identify the same zone; text codes such as A001 are not supported. The CSV identifier spelling is checked before floating-point parsing: out-of-range or fractional IDs are rejected, not rounded to a nearby zone. A Python API caller must also preserve its original values; precision already lost before calling the engine cannot be reconstructed.

    Every training census zone needs eligible grid pixels and a finite mean for each configured covariate. Zones without that support are reported as errors, including zones whose population is zero. Extra grid IDs without census totals are excluded from population outputs and recorded in diagnostics.

    Population CSV

    Use a CSV with unique, nonempty headers. Map the ID and population columns in Settings; names are case-sensitive and must differ. For example:

    id,pop
1,100
2,120
3,0

    Save this schema as population.csv and supply a zone raster with IDs 1, 2 and 3. These illustrative numbers are not a downloadable raster dataset or an accuracy benchmark. Even zone 3 needs valid training support.

    For a table headed zone_code,people, import it normally, then set Zone identifier to zone_code and Population total to people in Settings. Import does not require the default id/pop names; the engine checks the chosen mapping when Run starts.

    IDs must be unique, finite integers. Population totals must be numeric, finite and nonnegative; zero and fractional totals are accepted. Empty tables, duplicate IDs and missing values fail validation. Rows can appear in any order: joins and output checks use zone IDs rather than row positions.

    Additional columns are not automatically used as predictors. A nonmissing group column may be retained for explicitly configured grouped validation. Avoid derived column names such as dens, eligible_pixel_count and names used for covariate statistics. A population column named sum is supported without changing the source file.

    Covariates

    Provide aligned single-band numeric rasters. The model trains on each covariate's valid-pixel mean within a zone and predicts from selected covariate values at individual pixels. Pixels lacking any selected predictor receive NoData predictions; they are not filled with arbitrary sentinel values.

    Continuous measurements, distances, counts and meaningful binary indicators can be used. Categorical class codes are not encoded automatically: averaging arbitrary land-use codes is not meaningful. Derive appropriate indicators or other numeric representations before supplying categorical information.

    Missing covariates can reduce allocation support. A zone with positive population and no positive eligible prediction weight fails instead of losing its population silently. Confirm that the remaining support is appropriate for the study; conserved totals alone do not validate its geographic coverage.

    Optional masks

    The water mask is binary: 1 excludes a pixel and 0 retains it. Masked or NoData mask pixels are also excluded.

    The population-support mask is binary: 1 includes a pixel and 0 excludes it from constrained allocation. NoData support pixels are excluded. The engine creates a temporary constrained zone-ID grid while preserving the original zone identifiers. Do not supply a second, unrelated administrative-ID raster as the GUI population-support mask.

    An unconstrained population map is always produced. When a support mask is provided, a separate constrained map is produced and checked against the same census totals. The source masks and mastergrid are not modified.

    Training uses the mastergrid after water exclusion, not the constrained subset. The constraint limits the additional constrained allocation; it does not silently change the training-density denominator or replace the unconstrained result.

    Age and sex CSV

    Use the configured ID column and the same unique zone-ID set as the main population CSV. Group columns must match the supported complete naming pattern, for example f0, m0, f_0_4, m_5_9, f65+ or m65+. Names are matched case-insensitively; ambiguous duplicate group names are rejected. Unrelated metadata columns are ignored.

    Each group contains finite nonnegative totals and is joined by ID. Every group map is checked against that group's supplied totals. The engine does not require the sum of all group columns to equal the main population total. It records a keyed comparison in agesex/age_sex_totals.csv and a bounded mismatch summary in the run manifest. Check that consistency if the columns form a complete demographic partition: a mismatch is diagnostic, not forced rescaling or a hard error. Different row order does not change which zone receives a group.

    Both CSVs must contain the Zone identifier column selected in Settings. An age-sex import without that column is refused with an inline explanation; the original file and previous selection are retained. This is not an automatic ID conversion. If one dataset uses IDX and another uses id, first establish whether their values identify the same zones. Different ID systems need a verified correspondence table (crosswalk), applied explicitly to a separate copy. Never pair records by their row order or guess a mapping from similar ID suffixes. Preflight reports missing/extra zone counts and examples before modelling.

    For the population example above, a synthetic complete partition could be:

    id,f_0_49,m_0_49,f50+,m50+
2,40,40,20,20
1,35,35,15,15
3,0,0,0,0

    The reversed row order is intentional. Each row sums to its main population total here, but that relationship is yours to establish. For a partial set of age bands, a mismatch diagnostic may be expected. A regular id,pop census is not silently assigned as an age-sex table; select the optional age-sex role explicitly and supply supported group headers.

    Import behaviour

    Guided preparation

    The preparation wizard creates a separate new project. Its reference raster is a grid template (CRS, extent, transform and dimensions), not an implicit study-area mask. Zone validity comes from the original zone raster or explicitly chosen census polygons. The tool does not silently clip a whole census polygon to a smaller reference extent and allocate its full population into the remnant.

    Follow the wizard's four pages: Source data, Census columns, Predictors and support, and Review and create. Choose either an existing zone-ID raster or census polygons, map the CSV columns explicitly, and choose a new output folder. Use Check compatibility, read errors/warnings and coverage, then confirm Create new files; preserve the sources and current project. Only an accepted compatibility report enables preparation. If a source changes, check again. Choose Create prepared project, then Open prepared project when creation succeeds; add optional age-sex inputs afterward.

    Choose predictor quantity and resampling explicitly (1–32 covariates in this guided preparation version):

    • Continuous: nearest, bilinear or average alignment. The choice changes predictor values and must be appropriate for the measurement.
    • Binary indicator / mask: checked 0/1 values with nearest-neighbour alignment. Multiclass category codes must first be encoded as meaningful indicators; averaging arbitrary class numbers is not supported.
    • Count: already-aligned nearest passthrough only. Changing cell size or CRS requires a separately justified conservative aggregation method; this wizard refuses to pretend ordinary interpolation preserves counts.

    The derived GeoTIFFs embed the source validity in NaN NoData. Original GDAL resources, CSV and vector resources are fingerprinted, rechecked, and retained unchanged. Diagnostics include zone-ID matching, grid changes, missing support, joint predictor coverage, warnings and a full coverage CSV. Review the report before committing preparation. Unsupported or invalid data are not automatically repaired. Census vectors and tables are materialized and must fit engine memory; this is not a streaming vector ETL pipeline. Geographic coordinates and spans that require antimeridian splitting are refused before or after reprojection. Split/export them explicitly; the wizard does not guess a dateline repair. The GUI binds preparation to the inspected source hashes. A changed CSV, raster or sidecar requires a new compatibility check, not reuse of the old confirmation.

    Existing project files with external masks can be prepared into self-contained GeoTIFFs; direct GUI copy still rejects sidecars to avoid losing them. The prepared project includes a compatible config.yaml, derived data, report and provenance. After a late cancellation or forced stop, a newly requested output folder may remain. The message identifies a retained folder; treat it as potentially incomplete, inspect it separately and choose a new destination for retry. Cancellation never silently deletes or overwrites it.

    Age-sex inputs are added after opening the prepared project; this first wizard does not automatically copy a previously configured age-sex table. The original project retains it. Preparation is deliberately conservative: lack of jointly valid predictor support is diagnosed rather than resolved by implicit imputation.

    Direct file import

    New files are copied in cancellable background jobs into the project's data directory, normally <project>/data/. When typing a path manually, complete it and press Enter, Tab or leave the field to commit it. Enter confirms only that input, never Run or Cancel. If you click Run analysis with an uncommitted input path, that click commits the import first; wait for success and click Run analysis again. It does not calculate from the previous input. Intermediate keystrokes do not start imports; closing the dialog discards an uncommitted draft. Browsing still commits the selected path immediately. Existing destination names are never overwritten. A conflict dialog explains the selected role and offers:

    • Use verified existing file only when source/destination bytes match and raster sidecars do not make byte-only reuse unsafe.
    • Import separate copy under a new portable basename with the same extension. For example, elevation_copy.tif, not a folder path.
    • Cancel, retaining the previous input selection and both files.

    Hashing runs in the worker, not the GUI. A choice is rechecked before reuse or publication; changed sources/destinations are refused. A new-name collision also fails instead of overwriting. Selecting the ordinary canonical file already in the data directory reuses it in place, retaining its GDAL resources. File-symlink aliases and hardlinked existing collision targets are refused; select the canonical dedicated file or export a separate copy.

    Incomplete copies are staged and not registered. Clearing an optional file field or removing a covariate from the table removes only its configuration reference, not the physical file. Every new copied import verifies the source snapshot, staged bytes and current source before publication, even without a name conflict. This adds background reads but never installs packages or hashes on the GUI thread. Keep source files stable throughout import and analysis; this is change detection, not an adversarial point-in-time snapshot of another writer.
